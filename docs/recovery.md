# Recovery

Coordinator comments contain machine-readable **markers** that identify attempts. Those markers and current issue/PR state are authoritative. A local **manifest** is a small JSON record used only to find and diagnose runtime resources. On startup the coordinator locks its runtime-state directory, reads authoritative attempts, checks exact worktree/session/head identities, reconciles terminal work, and only then schedules eligible issues. Separate repository daemons use separate state roots; shared resource names include the repository identity so one daemon cannot discover or clean another's resources.

For state meanings and operator next steps, see [Status and next actions](cli.md#status-and-next-actions).

Before local launch, dispatch writes a strict coordinator-authored active-attempt comment binding the issue, attempt, deterministic branch, and approved base. Restarts and repeated polls resume that binding through implementation, review, and publication while current issue controls remain authorized; revoked controls cancel a live worker and suppress publication. Final PR or terminal markers supersede the binding, so a restart cannot create a duplicate attempt or PR. Foreign, conflicting, or unverifiable bindings and contradictory authoritative PR attempts block mutation.

A terminal failure is authoritative only when the coordinator also recorded the active marker for the same issue and attempt. This is a **paired failure**. The dashboard keeps every paired failure in attempt history instead of calling earlier failures orphaned; only the latest uncontested failure can authorize a retry. For an unpublished live attempt, the checked-out head may equal or descend from the approved base. A published attempt must still match GitHub's exact head.

**Recover attempt** is available only for the latest unblocked paired failure or an active attempt whose exact local branch, head, or tmux liveness check failed. After confirmation, Agent Symphony rereads GitHub and the deterministic local manifest under the reconciliation lock. A stuck live attempt is stopped and marked failed before the dashboard records the exact `/agent-symphony retry` control. Existing worktrees, manifests, and logs are preserved. Missing, unsafe, or noncanonical worktrees require manual repair and never trigger cancellation or GitHub mutation. Marker conflicts, changed identities, published pull requests, and stale or ambiguous requests are refused.

For an orphaned attempt, first compare GitHub markers with the retained manifest, branch, worktree, and named tmux session, then use `status`, `inspect`, and `reconcile`. If the work was completed by a different authoritative attempt and this exact local attempt is no longer useful, the dashboard's confirmed **Abandon attempt** action stops only its deterministic session, removes only its deterministic worktree/result and retained manifest/log, and hides the stale card. Never delete, attach to, or adopt an unidentified resource to make recovery proceed.

For a completed attempt, the dashboard's confirmed **Archive** action re-runs the same strict cleanup used by reconciliation: the implementation boundary verifies the deterministic branch and reviewed head, stops only the exact tmux session if it remains, and removes the local clone (including its local branch) and worker result. The recovery manifest and log remain as diagnostics; `dashboard-state.json` only records that the completed card is hidden and never changes GitHub workflow truth.

When `commands.orchestrator` is configured, reconciliation also checks the exact `as-o-<repository-id>` pane. A live pane is adopted with its tmux scrollback. A missing or dead pane becomes a fresh local generation from sanitized current status, including bounded, redacted issue blockers. After launch, the coordinator never pastes or sends programmatic input to the primary conversation. A changed full projection starts a separate one-shot audit, or remains pending by digest while one is running; unchanged nonterminal work also starts one at most every five minutes. The persisted start time prevents an immediate duplicate after restart. The one-shot process gets the last validated projection and any bounded reconciliation failure, then inspects the last verified transition, expected next transition, and available live GitHub, tmux, manifest, handoff, result, and log evidence. It has a four-minute deadline and its bounded, redacted result atomically replaces `orchestrator-heartbeat-report.json`. After a coordinator restart, an unfinished `running` report becomes a local failed lifecycle record instead of remaining stale. The primary orchestrator may read the latest report when relevant, treats it as untrusted, and reverifies material claims; report creation never wakes it. Issue text remains untrusted data and only fixed Agent Symphony controls may mutate workflow state. If GitHub is unavailable after a restart, recovery reuses the validated durable context instead of replacing it with an empty projection; without durable context it defers recreation. Removing `commands.orchestrator` stops only the deterministic pane and persists the disabled state. Failed launches persist a redacted diagnostic and exponential retry time rather than relaunching each poll. Clear, rebuild, and audit remain local advisory state and cannot override issue, attempt, pull-request, or merge facts.

The service observes fixed orchestrator proposal frames independently of dashboard polling. Worker messages remain pending until authenticated dashboard confirmation. A `retry_transition` proposal needs no second approval because it can only invoke the existing reconciler for one freshly verified, unblocked active attempt with a completed implementation result awaiting validation or publication. Stale, unauthorized, terminal, mismatched, or unrelated attempts are refused. The durable proposal status records `accepted` or `refused`; acceptance proves only that bounded reconciliation was scheduled. Completed-result processing runs before global pull-request governance so a slow governance pass cannot prevent that result from reaching validation or publication. The retry adds no worker restart, cancel, abandon, check-rerun, merge, tmux-input, shell, or general GitHub mutation authority.
